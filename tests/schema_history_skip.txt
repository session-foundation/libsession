# Revisions to skip in schema_history_check.sh, one short hash per line with a reason.
#
# For commits whose full_schema.sql was broken or mid-rework and was never released, so no database
# can have been created from it.  A file rather than a flag so that removing an entry is a
# reviewable change rather than a silent one.
#
# The hashes must be those of the commits as merged.  A branch rebased after its entries were
# written leaves them naming commits that are not in the history at all -- which skips nothing, and
# which the walk refuses rather than quietly checking everything they were meant to cover.
#
# Format:  <short-hash>  <reason>

# The attachment-availability branch (#168): every commit of it except the last, e5e14363, which is
# the only state of it anything can start from.
#
# It grew its schema over four migrations while it was being built and collapsed them into one
# (client 005_attachment_availability) before merging, then went on adding to that one -- the
# thumbhash column last.  So a database made partway through has either some of those four recorded
# and cannot take the replacement, or the replacement recorded without what was added to it later.
# None exists outside the branch, which is the whole reason they were collapsed -- one migration per
# merged change, not one per commit.
#
# Listed in full rather than only the commits that touched full_schema.sql.  The walk skips before
# it deduplicates, so omitting one merely promotes it to stand for the schema of the commit before
# it; and "no intermediate state of this work is a starting point" is the rule worth writing down,
